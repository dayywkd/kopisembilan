Laporan Pengukuran Kinerja Sistem Eksisting (Baseline)

Rekayasa Ulang Aplikasi Point of Sale (POS) Toko Kopi Sembilan dari Vanilla JS ke Svelte

Tanggal Pengujian

22 September 2026

Objek Sistem

Vanilla JS POS Eksisting

Basis Data

Supabase (3.826 Transaksi)

Metode Uji

Chromium DevTools Protocol (CDP)

1. Ringkasan Eksekutif

Pengukuran kinerja awal (baseline) ini dilakukan untuk menyediakan data empiris objektif bagi naskah publikasi jurnal ilmiah mengenai dampak rekayasa ulang arsitektur sistem kasir Toko Kopi Sembilan. Pengujian difokuskan pada tiga skenario penggunaan: Katalog Menu Kasir POS, Dashboard Harian, serta Dashboard Agregasi Besar (Bulanan dan Tahunan).

Temuan Utama: Sistem eksisting mengalami degradasi kinerja yang sangat parah saat memproses data agregasi. Pada periode Bulanan, thread utama browser terblokir total selama 7.024 ms (7,02 detik) dengan satu Long Task berdurasi 6.016 ms (6 detik). Pada periode Tahunan, sistem meluncurkan 42 request jaringan serentak dan konsumsi memori JavaScript membengkak hingga 16,24 MB.

3. Analisis Masalah & Hambatan Teknis (Bottlenecks)

  1. Kelemahan Arsitektur Agregasi Client-Side: Sistem eksisting mengunduh ribuan rekaman mentah dari Supabase dan memproses kalkulasi omzet, ranking produk, dan grafik secara manual menggunakan perulangan JavaScript di browser kasir. Akibatnya, pada periode Bulanan, layar kasir mengalami pembekuan (freeze) total selama lebih dari 6 detik.
  2. Reflow & Repaint DOM Berulang: Pembaruan antarmuka mengandalkan penyusunan string HTML (innerHTML += ...) yang menghancurkan struktur DOM dan memicu kalkulasi layout berulang (menghabiskan waktu 112 ms per render).
  3. Polusi Global Scope & Ketiadaan Tree-Shaking: Pustaka eksternal (Supabase JS, Chart.js, Lucide Icons, dll.) diimpor via tag CDN global tanpa pemisahan modul (code-splitting), menyebabkan konsumsi memori heap awal mencapai 13,10 MB.

5. Kesimpulan & Justifikasi Rekayasa Ulang

Hasil pengujian baseline ini membuktikan bahwa rekayasa ulang ke framework Svelte memiliki dasar ilmiah yang sangat kuat. Dengan arsitektur reaktif terkompilasi (compiled reactivity), pemangkasan Virtual DOM, dan optimasi pemanggilan data Supabase, seluruh Long Tasks dapat dieliminasi mendekati 0 ms serta menghasilkan waktu respon kasir yang instan.
